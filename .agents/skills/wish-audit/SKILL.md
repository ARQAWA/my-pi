# Аудит хотелок

Этот навык часть процесса разработки, не продукта. Он только читает цель. Меняй лишь список хотелок и свой отчёт. Код, тесты и документы цели не меняй.

Список: `/Users/arkadijcukavin/ai-project/my-pi-evidence/designs/wish-audit/WISHES.md`. Он накопительный: каждая хотелка в последней форме. Проверяй только эту форму. Ниже цитаты «заменила» только для понимания. Раздел «отменено» не проверяй.

1. Перед каждым аудитом обнови список по сообщениям владельца после его последнего обновления. Каждая хотелка в последней форме после каждой правки. Отменённые перенеси в раздел «отменено». Правь `wishes.json` и пересобери список через `build.py`.
2. Возьми цель: запрошенное состояние. По умолчанию ветка `main` на `origin`. Это может быть и тег или другая ветка на `origin`, локальный коммит или локальная папка. Исходный репозиторий не трогай.
   - ветка или тег на `origin`: склонируй в свою новую временную папку:
     `dir=$(mktemp -d) && git clone --quiet --depth 1 --branch <цель> "$(git remote get-url origin)" "$dir/repo"`.
   - локальный коммит: `dir=$(mktemp -d) && git clone --quiet --no-checkout <репозиторий> "$dir/repo" && git -C "$dir/repo" checkout --quiet <коммит>`.
   - локальная папка: читай на месте. Если `git status --short` не пуст, добавь к `sha` пометку «+ незакоммиченное».
   Возьми `sha`: `git -C <папка цели> rev-parse HEAD`. Читай только папку цели.
3. Раздели список по группам между помощниками, если он не влезает в контекст. Каждому дай шаги 4 и 5 этого навыка, путь списка, папку цели и номера хотелок.
4. Для каждой хотелки найди доказательство в папке цели. Годится: файл и строка кода или настройки, имя теста, id решения из `DECISIONS.md` вместе с кодом, который его несёт. Одно решение без кода не доказывает «выполнено». Требование к процессу или документу доказывает строка документа, который его несёт: `PROCESS.md`, `AGENTS.md`, скилл, `BACKLOG.md`.
5. Поставь итог:
   - **выполнено**: код или настройка делает то, что сказано. лучше с тестом. для требования к процессу или документу: документ говорит то, что сказано.
   - **не выполнено**: кода или строки документа нет, или они говорят иначе. укажи, где видно.
   - **неясно**: по коду не понять. например, вид, скорость, ощущение. или нужен запуск.
   Хотелка с меткой «отложено» или «в работе»: проверь так же, метку сохрани.
6. Запиши отчёт `/Users/arkadijcukavin/ai-project/my-pi-evidence/designs/wish-audit/AUDIT.md`:
   - первая строка: цель, её `sha`, дата.
   - итог: число «выполнено», «не выполнено», «неясно».
   - отдельный список «не выполнено»: номер, хотелка, одна строка почему.
   - таблица по группам: номер, хотелка, итог, доказательство.
   Пиши простым русским, коротко. Одна строка на хотелку.
7. Последним шагом проверь готовый отчёт слепым хай-ревью по навыку `highreview` (`bossy`). Порог тяжести, отклонение находок и объём повторной проверки бери из навыка `reviewer` и `PROCESS.md`. Дай ревьюеру список хотелок, отчёт, папку цели и её `sha`. Он проверяет каждый итог по точной цитате действующей хотелки и доказательству в цели. Если одно ревью не вмещает весь отчёт, раздели его по тематическим разделам `WISHES.md` так, как они стоят в списке: каждая хотелка в одной части. Ревьюер называет в `CHECKED` каждую хотелку, которую не проверил. Непроверенная хотелка значит, что часть не `CLEAN`. Не завершай аудит, пока каждая часть не `CLEAN`.
8. Если создавал временную папку, удали только её: `rm -rf "$dir"`.
9. Верни вызывающему только счёт итогов и путь отчёта.
