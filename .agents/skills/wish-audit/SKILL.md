# Аудит хотелок

Этот навык часть процесса разработки, не продукта. Он только читает. Код, тесты и документы не меняй.

Список: `/Users/arkadijcukavin/ai-project/my-pi-evidence/designs/wish-audit/WISHES.md`. Он накопительный: каждая хотелка в последней форме. Проверяй только эту форму. Ниже цитаты «заменила» только для понимания. Раздел «отменено» не проверяй.

1. Возьми цель: ветку или тег на `origin`, по умолчанию `main`. Склонируй её в свою новую временную папку, исходный репозиторий не трогай:
   `dir=$(mktemp -d) && git clone --quiet --depth 1 --branch <цель> "$(git remote get-url origin)" "$dir/repo"`.
   Возьми `sha`: `git -C "$dir/repo" rev-parse HEAD`. Читай только `$dir/repo`.
2. Раздели список по группам между помощниками, если он не влезает в контекст. Каждому дай этот навык, путь списка, папку цели и номера хотелок.
3. Для каждой хотелки найди доказательство в папке цели. Годится: файл и строка кода или настройки, имя теста, id решения из `DECISIONS.md` вместе с кодом, который его несёт. Одно решение без кода не доказывает «выполнено». Требование к процессу или документу доказывает строка документа, который его несёт: `PROCESS.md`, `AGENTS.md`, скилл, `BACKLOG.md`.
4. Поставь итог:
   - **выполнено**: код или настройка делает то, что сказано. лучше с тестом. для требования к процессу или документу: документ говорит то, что сказано.
   - **не выполнено**: кода или строки документа нет, или они говорят иначе. укажи, где видно.
   - **неясно**: по коду не понять. например, вид, скорость, ощущение. или нужен запуск.
   Хотелка с меткой «отложено» или «в работе»: проверь так же, метку сохрани.
5. Запиши отчёт `/Users/arkadijcukavin/ai-project/my-pi-evidence/designs/wish-audit/AUDIT.md`:
   - первая строка: цель, её `sha`, дата.
   - итог: число «выполнено», «не выполнено», «неясно».
   - отдельный список «не выполнено»: номер, хотелка, одна строка почему.
   - таблица по группам: номер, хотелка, итог, доказательство.
   Пиши простым русским, коротко. Одна строка на хотелку.
6. Проверь готовый отчёт слепым хай-ревью по навыку `highreview` и его правилам `reviewer`. В каждом круге запусти нового `bossy`. Дай ему список хотелок, отчёт, папку цели и её `sha`. Он проверяет каждый итог по точной цитате действующей хотелки и доказательству в цели. Исправь все находки в отчёте, включая счёт, и запусти нового `bossy` на весь отчёт. Повторяй до `CLEAN`. Не отклоняй находку без нового слепого круга. Не завершай аудит без `CLEAN`.
7. Удали только свою временную папку: `rm -rf "$dir"`.
8. Верни вызывающему только счёт итогов и путь отчёта.
