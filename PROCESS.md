правила действуют только в процессе этого проекта.
**запрос**
1. делай только заказанное и согласованное. несогласованное покажи с доказательством, спроси владельца. удаляй только после ответа владельца. оставляй только с его явного разрешения.
2. прямой заказ разрешает простую работу. её предел: два SP. все требования должны быть выполнимы. обсуждение разрешением не считается. спорное оставь до ответа владельца.

**план и сложность**
3. выбирай кратчайшее решение без лишнего кода. SP означает сложность, не время. задачу крупнее двух SP раздели. пиши понятный код, дели без числовых лимитов.
4. спроектируй любую задачу сначала. простая задача до двух SP? все требования выполнимы? тогда делай сразу. задача больше двух SP? принеси проект, обоснование и план. предложи самый лёгкий вариант. проект держит всё заказанное и ничего сверх. лишнее считаешь критичным? спроси владельца и пометь критом. проект проверяет spotty до показа. не влезаешь в заказанный объём SP? скажи почему, предложи лёгкий вариант. всё общение строго по правилу дислексии.
5. план и макет показывай по заказу. свыше двух SP показывай всегда. согласование не нужно только до двух SP. неясный объём сначала уточни.

<a id="isolated-parallel-execution"></a>
**работа**
6. ветка хранит изменения отдельной задачи. worktree означает отдельную рабочую папку. создай их от release, ветки сборки.
7. координатор поручает работу, кроме приказа работать самому. ребёнок знает свою роль. вложенных исполнителей разрешай явно. проверяющие своих исполнителей не запускают. stop делай в одном вызове со следующим шагом.
8. одна задача одновременно, если иначе не заказано. тесты не создают отдельную очередь. ведение очереди не отдельная задача. застрявшая задача ждёт, бери следующую разрешённую.
9. код, правки программ: gpt-6.1-terra xhigh, claude-sonnet-5-5 high. механика, простые действия: gpt-6.1-terra medium, claude-sonnet-5-5 medium. обычное, простой поиск фактов: gpt-6.1-terra high, claude-sonnet-5-5 high. аналитика, ресёрч, аудиты, поиск причин, замеры с выводами, сравнение вариантов: gpt-6.1-sol medium, claude-opus-5-5 medium. сложнейшее, трудные задачи: gpt-6.1-sol medium, claude-opus-5-5 medium. проектирование всегда в классе design. точные пары в блоке ниже.
10. модель выбирает случайный механизм, не агент. high означает сильное рассуждение, medium среднее. low означает слабое.

<a id="sufficient-proof-without-idle-reruns"></a>
**тесты**
11. малой правке поведения дай свой тест. проверяй только поведение, затронутое изменением. новой функции один основной сценарий, критические ветки. реальному багу один тест повторения.
12. вызывай функцию через её обычный вход. проверяй результат, не внутренние вызовы. тест должен ловить отсутствие исправления. тест пиши от требования, не реализации.
13. моки заменяют внешний мир управляемыми данными. подменяй сеть, модель, часы и Pi. свой код не подменяй. тесты не запускают сеть и настоящий Pi.
14. тесты без продукта и связок настоящих систем. часы и данные всегда одинаковые. случайности нет, порядок тестов не важен. один процесс, без ожидания настоящего времени.
15. байт в байт сверяй только неизменные части. изменяемые части так не сравнивай.
16. маленькие данные в тесте, временные папки допустимы. тест длится миллисекунды, набор расширения секунды. не оставляй слабые, повторные или пропущенные тесты.
17. запускай лишь тесты затронутого расширения. полный прогон делает только выпуск. тексту никаких запусков, сверь только цитаты и ссылки. повтор допускай после исправлений или новых данных. тяжёлые замеры гоняй в CI. логи замеров сохраняй.

<a id="independent-review"></a>
**независимая проверка**
18. исполнитель сам ведёт проверку, кроме записей. записи: BACKLOG, DECISIONS, DECISIONS-ARCHIVE, INDEX, INSTALL, манифест. сначала коротко проверь себя: тесты затронутого поведения. продукт запусти, когда возможно и разрешено.

   перечитай правку по словам владельца, исправь ошибки. тексту запусков нет, только цитаты и ссылки.
19. затем blind через spotty запускает форк selfcheck, не ты. bossy означает глубокую проверку по заказу. находке нужны доказательство, условие и неверный результат. P0 критично, P1 серьёзно, P2 средне.

   данным, безопасности, удалению минимум P2. пропуск или добавление оценивай по последствиям. P3 исправляй вместе с P0–P2.

   только P3? это CLEAN, их не упоминай. P4, вкусовщину, безвредные предположения не сообщай. каждый проверяющий отдаёт все допустимые находки сразу.

   исполнитель исправляет их одним набором. ошибки формата исправляет сам, без нового круга. после исправлений запускает нового проверяющего до CLEAN. тот проверяет исправления, строки и затронутые пути.

   весь объект заново не проверяет. доказательства уточняй у того же проверяющего. нет нужных доказательств?

   проверка не завершена. вызывающему верни один отчёт: проблемы, исправления, CLEAN. сверх заказа ничего не исправляй.

   закончил работу и обычные проверки? запусти навык selfcheck: форк себя с fork_turns all. форк делает шаги 18 и 19 сам и возвращает один отчёт. ты ждёшь, не правишь объект и не запускаешь blind до форка. форк не запускает второй форк.
20. выпуск с кодом: отдельно проверь код и тесты. code-reviewer проверяет код, test-reviewer проверяет тесты. spotty: gpt-6.1-terra medium. bossy: gpt-6.1-terra xhigh. остальные проверяющие: gpt-6.1-terra high.

<a id="delivery"></a>
**доставка**
21. squash объединяет изменения задачи одним коммитом. после проверки squash задачи направляй в release. записи коммить прямо в main, без ветки, прогонов, выпуска и CI. инструкции, PROCESS, AGENTS и .agents: ветка и spotty, потом прямо в main.
