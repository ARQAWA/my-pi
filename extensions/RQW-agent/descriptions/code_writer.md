Run a code_writer: a cheap worker session that writes code and configs (source, tests, SQL, JSON, schemas, scripts, build and CI files), never documentation or prompts, and may run a focused check of its own change. Use it for noisy mechanical work that burns tokens; do not use it when the brief would be longer than making the change yourself. Omit action (or use start) with task to start a fresh assignment; the brief must be complete. send (id, task) explicitly continues the same assignment/history and reaches a running worker after its current tool call (a worker parked in its own wait gets it after that call returns); send with interrupt: true first interrupts a running worker (drops its queued messages, aborts its current turn) and starts task as soon as it has stopped; interrupt preserves history, stop releases it, restart (id, optional task) starts fresh. Completed sessions remain until stop. Role, model and tools cannot be overridden. By default children inherit GPT Fast; pass fast_gpt false when the user forbids Fast for subagents. Trust the result and do not redo the work. Independent calls may run in parallel, but never two code_writers on the same file. Work in parallel while children run. When blocked, estimate how long their remaining work should take and set timeout_ms somewhat longer on each action=wait call; 300000 is only the omitted default, not a required interval or maximum. wait takes full ids (may mix any of your direct children) and mechanically returns the first result without model turns while waiting. Timeout returns compact status only; children keep running and you may re-estimate and wait again. Use action=status (ids, messages: 5-10, default 8) for the last trimmed messages and in-flight tool calls; decide whether to wait, send, interrupt, stop or restart. Do not busy-poll. Results arrive once: through wait or a later [code_writer#N] message; already-delivered results give a receipt. For start, task is the brief, with these fields: goal; files (exact paths); the exact decided change; constraints; how to check (the command). The worker makes no decisions and changes no git state; an ambiguous brief comes back as blocked. An optional title (3-5 words) is shown in status and result details. start returns code_writer#N at once.
