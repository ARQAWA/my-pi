Run a shell_runner: a cheap worker session that runs the commands you give it and reports the outcome. Use it for noisy mechanical work (builds, test suites, installs, service starts, long logs, read-only git) that burns tokens; do not use it when the brief would be longer than running the command yourself. One assignment per call; every call starts with a fresh context, so the brief must be complete. Trust the result: per command it returns the exit code, duration, a one-line outcome, the verbatim error lines and the path of the full output. Independent calls may run in parallel. Its result arrives later as a message [shell_runner#N] ...; do not wait or poll. Parameter: task, the brief, with these fields: directory; commands in order; timeout; on failure stop or continue. The worker chooses no other commands, fixes nothing and changes no git state. Returns shell_runner#N at once.
