Run a shell_runner: a cheap worker session that runs the commands you give it and reports the outcome. Use it for noisy mechanical work (builds, test suites, installs, service starts, long logs, read-only git) that burns tokens; do not use it when the brief would be longer than running the command yourself. One assignment per start; each start uses a fresh context, so the brief must be complete. Trust the result: per command it returns the exit code, duration, a one-line outcome, the verbatim error lines and the path of the full output. Independent calls may run in parallel. Omit action (or use start) with task to start a fresh assignment. send (id, task) explicitly continues the same assignment/history and reaches a running worker after its current tool call (a worker parked in its own wait gets it after that call returns); send with interrupt: true first interrupts a running worker (drops its queued messages, aborts its current turn) and starts task as soon as it has stopped; interrupt preserves history, stop releases it, restart (id, optional task) starts fresh. Completed sessions remain until stop. Role, model and tools cannot be overridden. By default children inherit GPT Fast; pass fast_gpt false when the user forbids Fast for subagents. Work in parallel while children run. When waiting, estimate how long their remaining work should take and set timeout_ms somewhat longer on each action=wait call; 300000 is only the omitted default, not a required interval or maximum. Saved sessions survive a Pi restart; ids stay valid. wait takes full ids (may mix any of your direct children). If a selected result is ready it returns at once; otherwise it returns reason waiting at once and your turn ends with no further model request, and one `[shell_runner#N]` notification message wakes you later (first result, all results with until all, an alert, or the timeout_ms deadline). Pass blocking true to hold the call instead (inside a codemode script a wait always blocks). Your messages and Esc do not stop children. The timeout returns compact status only; children keep running. Use action=status (ids, messages: 5-10, default 8) for the last trimmed messages and in-flight tool calls; decide whether to wait, send, resume, interrupt, stop or restart. resume (id) retries an interrupted or restart-lost child's cut-off request with no new message; it never replays a tool call that may have had side effects, and an idle child needs send. Do not busy-poll. Results arrive once: through wait or a later [shell_runner#N] message; already-delivered results give a receipt. For start, task is the brief, with these fields: directory; commands in order; timeout; on failure stop or continue. The worker chooses no other commands, fixes nothing and changes no git state. An optional title (3-5 words) is shown in status and result details. start returns shell_runner#N at once.
