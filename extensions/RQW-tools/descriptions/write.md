Create or overwrite files; missing parent directories are created. For one file give path and content; for several files use one call with files: [{path, content}, ...]. Never both forms in one call and never one file twice. Use write for new files and full rewrites; change part of a file with edit. A response has an output limit: write a file over about 400 lines in parts, each part in its own response: the first with write, then each next with edit whose oldText is the unique last lines of the file and whose newText is those lines plus the next part. The result has per-file status lines. Cancellation or an I/O error can happen after a file changes. A cancelled file reported as "Possibly changed" has details.files[].outcome = "possibly_changed": read it before retrying; do not blindly resend cancelled or I/O-failed files. Successful files retain any stock metadata in details.files[].details. A write over a file you read is refused once if someone else (a job, another agent, a program) changed the file after you last read it; read it again, or repeat the identical write to overwrite.
Trust a file's successful write: your content is in place, so never reread it just to verify your own change. Failed, cancelled and possibly changed files get no such trust; reread when something outside your call may have changed the file.
