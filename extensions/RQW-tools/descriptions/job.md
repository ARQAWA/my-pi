Wait for, check or kill your background jobs. A bash, codemode, rqw_readfile, edit, write, rqw_rg or rqw_glob call still running after 12 seconds returns a job id (job#N) and keeps running. Calls run independently; wait for a job before anything that needs its result.
- wait: call this tool directly in a wait-only batch, not inside codemode. A nested wait returns direct_wait_required; a mixed batch returns work_pending. Neither consumes results. The call blocks until one of `ids` ends (with any other that ends within a quarter second), `timeout_ms` passes, or, with `until` (a regular expression), a job's output matches it; the result lists the finished jobs and the status of the rest. A job that has already ended returns its full result at once. Jobs keep running after a timeout. Estimate how long the job still needs and set `timeout_ms` somewhat longer; 300000 is only the default when omitted.
- status: state, exit code, elapsed time, the last `lines` lines of output (default 20) and the log file of each job in `ids`, or of all your jobs without `ids`. Read the log file with rqw_readfile or rqw_rg for more.
- kill: stops a process job and all its child processes. A running file-tool call finishes on its own.
A background job is independent of the user's messages and of Esc: it stops only on `job kill`, a child's interrupt or the end of the session. Kill jobs you no longer need before your final answer, unless the user wants them left running.
