# RQW-browser

The independent `browser` tool provides the first lifecycle skeleton. `open` creates a named tab, `tabs` lists tabs, and `close` releases one or all. `call` accepts a sequential `{method, args}` chain. `run` executes a short ordered list of semantic actions in an isolated model context. Page helpers beyond the observation and action sets below are also unavailable. `open` also takes `wait_until` for its `url` and `dialogs` (`accept` or `dismiss`).

By default the extension uses system Chrome when present. Otherwise it downloads Chrome for Testing into the user's cache on first use. The dependencies are loaded only on first use. `app.path` chooses an executable; `app.cdp_url` connects to an existing browser. `headed` selects visible mode; headless is the default. Managed browsers use a temporary, separate profile unless `app.args` explicitly supplies `--user-data-dir`. No administrator privileges or system-wide browser installation are required.

Current browser actions use CDP, not WebDriver BiDi, so they do not reach the `chromium-bidi` Zod parser affected by GHSA-mrhx-c7xc-m3w5.

Each named tab has its own browser connection. Closing or session shutdown terminates default managed browsers and removes their temporary profiles. An application launched with `app.path` remains running unless `close` sets `kill: true`; only its own live child process is terminated. Its temporary profile is removed after that process exits. Connected browsers are disconnected, not terminated; their pages are not closed. An abort or timeout interrupts the call and cleans up a partially acquired managed browser. `timeout` is in seconds, default 30, clamped to 1–300. Page content and CDP sessions belong to the user; a connected browser may contain real login state.

## Semantic run contract

`run` takes exactly one non-empty `name` or `url`, one to eight non-empty `actions`, a non-empty `expected` result, optional `conditions` and `timeout` in seconds. Conditions have `kind` (`text_visible`, `url_contains`, `control_enabled`), non-empty `value` and `effect` (`require`, `stop_if`). The timeout defaults to 60 seconds and must be 1–120. Input and each model request are limited to an estimated 12,000 tokens. A URL opens a new named tab which remains available to `call`.

The caller's provider selects the authenticated model without fallback: `anthropic/claude-haiku-5-5` at `medium` or `openai-codex/gpt-6-luna` at `high`. Missing authentication, model or effort is an error before browser work. The result contains `result`, `reached`, `page` (`name`, `url`, `title`, `summary`) and `stopped` (`condition`, `limit`, `cancelled`, `error`, or null). Cancellation stops model requests and waits, starts no new actions and leaves the tab open. An already dispatched action may still finish; it is not rolled back or retried. Inspect a fresh `view` before the next run.

## Page observation

Helpers: `url`, `title`, `view()`, `observe({selector?, compact?, viewportOnly?, includeAll?})`, `ariaSnapshot(selector?, {interactive?, compact?, urls?, diff?})`, `text`, `html`, `value`, `attr`, `count`, `isVisible`, `frames()` and `frame(selectorOrNameOrUrl)`. `id(n)`, `ref(id)` and `frame(...)` return a handle; the next chain step is the one method called on it (`text`, `html`, `value`, `attr`, `isVisible` on elements; the selector reads and `ariaSnapshot` on frames).

- `view()` renders the page and its accessible frames as Markdown, with names, values, states and `[id:N]` for controls. It uses `observe({includeAll:true, compact:true})`; its ids work with `id(n)` only until the next observation or page change. An `INCOMPLETE` warning names frames that could not be read. Canvas without accessible text is not represented.
- `observe` numbers interactive nodes of the page and its frames from the accessibility tree. Each observation renumbers from 1. An id is stale when its frame loaded another document, its node left the document, or a back/forward cache restore happened; the errors are oh-my-pi's (`Element id N is stale. Run tab.observe() again.`, `Unknown element id N. ...`). A stale frame id clears all ids.
- `ariaSnapshot` runs Playwright's ARIA code (`aria-snapshot.bundle.txt`, copied unchanged from oh-my-pi 18.8.9) in the frame's isolated world. Refs (`e5`, `@e5`, `aria-ref=e5`) renumber on every snapshot and fail with `Unknown ARIA ref` after navigation or re-render. Refs of a frame snapshot are local to the frame; `tab.ref` resolves main-frame refs only.
- Selectors take CSS plus `aria/`, `text/`, `xpath/`, `pierce/` and the extension's `label/`, `placeholder/`, `testid/`, `alt/`, `title/`, `role/` handlers, registered once on first open. Playwright-only selectors fail fast. Selector reads on the tab give `null`, `0` or `false` for no match; frame reads throw `Failed to find element matching selector` for `text`, `html`, `value` and `attr`, as oh-my-pi's do.
- A frame that does not answer within 5 s is left out of `observe`.
- Licenses: `THIRD-PARTY-NOTICES.md` and `LICENSE-APACHE-2.0.txt`.

`open` accepts `viewport: {width, height, scale?}` before navigation. `styles(selector, properties?)` reads computed styles; element handles accept `styles(properties?)`. `evaluate(expression)` runs an expression on the tab or frame. To pass arguments, provide function source and arguments, for example `evaluate("(x) => x * 2", 3)`. A frame's `screenshot(selector)` returns its element as a Pi image. Element handles accept `press(key)` including combinations.

## Navigation and actions

Helpers of the tab: `goto`, `back`, `forward`, `reload`, `pushState`; `click`, `dblclick`, `hover`, `focus`, `check`, `uncheck`, `type`, `fill`, `select`, `scrollIntoView`, `press`, `keyDown`, `keyUp`, `mouseMove`, `mouseDown`, `mouseUp`, `clickAt`, `wheel`, `scroll`, `drag`; `waitFor`, `waitForSelector`, `waitForUrl`, `waitForText`; `screenshot`; `dialog`, `handleDialog`, `setDialogs`; and the reads `box`, `isEnabled`, `isChecked`. Element handles from `id(n)` and `ref(id)` take the element actions and the reads. A frame handle takes `click`, `fill`, `type`, `press`, `waitFor` and `waitForSelector`. Not here: `waitForNavigation`, `waitForResponse` and highlight. Cookies, storage, uploads and downloads are in the next section.

- Navigation waits for the main document only, so a frame that never finishes cannot hold it (`waitUntil` defaults to `load`). A navigation that outlasts the call's budget is stopped, and the error says how to retry. `goto` forgets every observed id, as in oh-my-pi; ids and refs of a document that loaded again fail as in the observation section.
- Actions run under oh-my-pi's 8 s ceiling, capped by the call's `timeout` less 1 s. A timeout names the operation and adds what is known: why a click was refused, how many elements the selector matches, and an open dialog. oh-my-pi's 2 s fail-fast for a selector that matches nothing is not ported; a wrong selector fails at the action ceiling.
- A click scrolls the element into view, waits until it stops moving, and refuses one that is hidden, off screen or covered, naming the covering element. `text/` selectors click the first visible match.
- `fill` clears and retypes without waiting for animation frames; `select` matches an option value first, then its label, and throws before touching the select when nothing matches. `press` takes a key or a combo such as `Shift+Tab`; on macOS `Meta+a`, `Meta+c`, `Meta+v`, `Meta+x`, `Meta+z` and `Meta+Shift+z` also name Chrome's editing command, which a plain key event does not reach.
- `waitFor*` timeouts are in milliseconds: none means the action ceiling, 0 or Infinity the longest wait the call allows, a larger value is clamped to that. They return nothing, since a chain cannot carry a handle; act on the element in the next step. `waitForUrl` takes a string the URL must contain (a RegExp only inside the later `run`).
- `screenshot({selector?, fullPage?, format?, quality?})` returns a Pi image result next to the JSON summary (`mimeType`, `width`, `height`, `originalWidth`, `originalHeight`). The image goes through Pi's `resizeImage` to at most 1024 px and 150 KB, as oh-my-pi does; the summary gives the original size for converting coordinates. An owned browser comes to the front first. A connected browser is never brought forward; its hidden tab is refused. No file is saved.
- Dialogs: without a policy, alerts and `beforeunload` prompts are accepted at once; confirms and prompts stay pending for `handleDialog({accept, text?})`. `setDialogs("accept" | "dismiss" | null)` sets the policy and settles a pending dialog. A pending dialog is forgotten when the main frame navigates. A click that opens a confirm or prompt at once stays blocked by the browser until the dialog is handled, and a chain cannot handle it meanwhile: set a policy first, or open the dialog from a timer (it shows up in `dialog` a few milliseconds after the click). The timeout of the blocked click names the dialog, and `handleDialog` still works afterwards.

## Sessions and files

Helpers of the tab: `cookies`, `setCookies`, `clearCookies`, `storage`, `setStorage`, `clearStorage`, `saveState`, `loadState`, `uploadFile` (also on `id(n)` and `ref(id)` handles), `waitForDownload`, `downloads`. `open` takes `persist` and `downloads`.

- Cookies and storage follow oh-my-pi: `setCookies` takes objects, `Cookie:` headers, DevTools cURL dumps or JSON arrays, with an optional trailing `{domain}` or `{url}`; a malformed input gives `tab.setCookies() received malformed cookie input`. Storage is the current origin's `local` or `session` area; a value that is not a string is stored as JSON.
- `saveState(path?)` writes the browser's cookies and the current origin's storage to a JSON file and returns its path. Without a path it is `<agent dir>/browser/state/<tab>.json` (normally `~/.pi/agent/browser/state`), `~/` or a path relative to the session folder otherwise. The file holds logins, so it is written readable by its owner only (`0600`, the default folder `0700`) and replaced in one step. `loadState(path)` restores the cookies, then the storage of the current origin. Storage of other origins is restored through a hidden page, only for a managed headless browser and only when the origin has no session storage (closing that page would lose it); the rest is named in `skippedOrigins`. Session cookies are in the file, so they come back too.
- `persist: true` makes a managed browser use the extension's own profile, `<agent dir>/browser/profiles/<executable>-<hash>`, and keeps it after close. A login the site stores in an expiring cookie or in local storage is still there on the next `persist: true` open; session cookies are not (Chrome drops them on exit), which `saveState` and `loadState` cover. One profile per executable, held by one tab of this session at a time (`The persistent profile of this browser is in use by tab ...`). Another Pi session or a Chrome that already uses the profile is not detected here; Chrome then fails to start. Without `persist` the profile is temporary as before. An `app.args` `--user-data-dir` is the caller's profile and `persist` changes nothing there; a connected browser has no profile of ours. The user's own browser profile is never opened.
- `uploadFile(selector, ...paths)` goes to `<input type=file>` directly. Any other element is clicked and, when it opens a file chooser within 400 ms, the chooser takes the files; otherwise the files are dropped on it as `dragenter`, `dragover` and `drop` events. Paths are checked for presence before the element is looked up, and relative ones start from the session folder. The drop path knows a dozen common file types and gives the rest `application/octet-stream`.
- A managed browser tracks downloads from `open`: Chromium saves each file under its download id in a folder of its own and the extension moves it to the name the page suggested (only the last path segment, never over a directory or symlink). Without `downloads` that folder is a temporary one, removed on close when it is empty; `downloads: "dir"` (relative to the session folder) names a folder that is never removed. A connected browser is left alone until `downloads` is set or `waitForDownload` is first called; that changes the download folder of the whole connected browser context and a download started before is not seen. `waitForDownload({timeout?})` (milliseconds) returns `{path, suggestedFilename, url, bytes}` of the next finished download no call has taken, `downloads()` lists all of this tab. Only downloads started by the tab's own frames count.

## VDI checklist for PCLI

After the browser reaches main and the new PCLI is published, check inside your VDI:

1. PCLI loads the browser extension and exposes the `browser` tool.
2. The permitted browser EXE starts without administrator rights.
3. The user folder permits profile creation, download and extraction.
4. The proxy, certificates and download servers permit Chrome for Testing when needed.
5. CDP and the `RemoteDebuggingAllowed` and `DeveloperToolsAvailability` policies permit the intended sites.
6. Open a page, type, take a screenshot, cancel an operation and close the browser.

Do not bypass corporate policies. Windows PCLI and VDI have not yet been verified.

Test with `npm run check -- --test 'test/extensions/RQW-browser/*.test.ts' test/isolation.test.ts`.
