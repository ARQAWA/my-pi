# RQW-history-edit

In the TUI, double Escape in an empty idle editor, with no subagent, review or background process running, opens messages from the current branch. `/edit-history` opens the same list. Enter selects a message for editing. Escape restores the draft and returns to the list; Escape again closes it.

Navigation stops at the first and last message. Owner: «Неудобно в самый верх и самый низ переезжать.»

Enter sends the edited text, the selected message's images and any new images. It permanently replaces the current session file with the path before that message. Other branches in that file are removed. The current session name, labels on retained entries and subagent records are retained. Subagent files and delivered-result receipts are not removed. Existing `/fork` files are unchanged.

Before navigation, the original branch is anchored and the session file is copied to a sibling `.rqw-edit-<pid>.bak` file without loading it into a Buffer. The replacement is written one JSONL entry at a time to a temporary file before renaming it over the session. The backup is removed only after a successful replacement, session switch and acceptance of the edited message. If sending fails before the message is in the history, the old history is restored and the draft stays in the editor; a run error after acceptance keeps the cut. A failed edit renames the backup back, restores the previous branch and keeps the draft; the restored branch is also retained on resume. If the backup cannot be restored, it stays on disk and its path appears in the error. Recovery after a session replacement runs through a fresh command context, not the invalidated context. If recovery itself fails, the next submit retries restoration of the original leaf. A successful retry consumes that submit, exits edit mode, keeps the typed text in the editor and shows `Previous branch restored.` as an info notice. The next Enter follows Pi's normal submit path for messages, built-in commands and shell input. Another recovery failure keeps the draft blocked and shows an English error. A session switch also clears the block.

Retained subagent records before the first discarded child record are not copied again. From that point, child records are replayed in file order so later state still wins. This stops repeated edits from doubling retained child records. It does not repair already bloated files.

The edit is refused while a subagent or background process is running (counts from every offer on `rqw:running-counts:offer`), or when the session has no saved file; the list does not open then, a warning shows and the draft is unchanged. A busy session cannot be edited. The edit uses Pi's public session APIs.

## Large sessions

Pi 1.4.0 `buildContextEntries` passes the whole tail after the latest compaction to `push(...)`. A tail of about 120000 entries throws `RangeError: Maximum call stack size exceeded` when a session is opened, switched, edited or sent. `projection.ts` patches `SessionManager.prototype.buildContextEntries` and `buildSessionProjection` in memory: Pi's own call runs first and only a `RangeError` switches to a copy that uses loops; a manager that overflowed once skips the stock call afterwards. The patch is installed when the extension loads, only if a probe branch gives the same result as Pi's methods and both methods are writable. Any other shape leaves Pi stock. Installed Pi files are not edited. The wrappers stay for the process; a reloaded module puts Pi's methods back and installs its own, so `/reload` applies the new code (wrappers that another extension covered, or that an older release left unrecorded, stay until a restart).

Callers that hold an entry list instead of a manager read the guarded function from `globalThis[Symbol.for("rqw:safe-projection:v1")]`. Without this extension they use Pi's function. Pi's own compaction preparation calls the projection through a module binding that cannot be patched; it stays stock. Compacting a session with such a tail is not a crash: manual compaction shows Pi's error, and automatic compaction fails before Pi starts reporting, so it returns without a message and the session is not compacted.

On every Pi update the oracle tests in `test/extensions/RQW-history-edit/projection.test.ts` compare the copy with Pi's functions. `scripts/measure-safe-projection.ts` prints Pi's and the copy's time in CI, without a time assertion.

Disable independently with `-extensions/RQW-history-edit/index.ts`, then restart (a loaded projection patch stays until then). Tests: `test/extensions/RQW-history-edit/`. Decisions: [History edit](../../DECISIONS.md#history-edit), `[D-HISTORY-BIG-SESSION]`.
