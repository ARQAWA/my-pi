# RQW-predictions

A gray next-message suggestion in the empty input of the main interactive chat. Tab turns it into ordinary text.
Nothing is sent by the extension; every other mode and every child session stays quiet.

## Behaviour

- Nothing is generated by itself. A finished answer (`turn_end`, outcome `completed`, stop reason `stop`) only drops the old
  request and suggestion. No retries, no total limit.
- Ctrl+E works when the current branch has both a user and an assistant message, including immediately after resume or a session switch. A clean branch has no hint and Ctrl+E does nothing.
  In every chat state (turn running, background only, idle, queued messages) it works: it generates at once, also
  repeats a failed run, and pressed while a request runs it cancels it: the footer status turns maroon for 2000 ms.
  Ctrl+R is freed from Pi's actions and does nothing here; RQW-send-now takes it to restart an interrupted turn.
- The request is a fork of what the main model last saw (the shared `rqw:context-fork:v1` contract, as `/btw`);
  without a transport offer it is one direct `streamSimple` call. The last user message is the prompt Codex serves,
  the JSON reply instruction and the owner's rule «if there is no obvious next user message, set suggestion to null».
  The model and effort are the chat's. Tools never run. A hosted-tool refusal (`decline("unsupported_hosted_tools")`) is final.
- The prompt comes from `codex-prompt.ts`: Codex's own endpoint, the saved `openai-codex` login read-only, a 300000 ms cache.
  Predictions therefore need that login also in an Anthropic chat.
- The suggestion is kept until the next finished answer. Typing hides it, clearing the input shows the same one again.
  It is drawn whole and wrapped, in the theme's `dim` colour; the real buffer stays `""` until Tab.
  Tab inserts it as one undoable edit. Enter, Right, Shift+Tab and key releases do nothing special.
- In an empty input the key hint is dim and italic, two spaces after the cursor. A chat with a saved Codex login and an
  answer shows `ctrl+e to suggest` in every state, also while a request runs. It is the only hint of the input. The Esc
  hints are not in the input: RQW-statusbar draws them on the activity line. A ready suggestion is always drawn, in every chat state, and no hint covers it; it stays
  non-italic. Typing, including a space, hides both. Hints never enter the buffer or history.

## Keys

`keybindings.ts` wraps the live Pi keybindings manager in memory and takes Ctrl+E and Ctrl+R away from every action:
the line end keeps End; session rename in `/resume` loses Ctrl+R (use `/name`); Ctrl+R then does nothing in this extension. Nothing is written to any settings file.
If the manager has an unknown shape nothing changes, a warning is shown and the manual keys stay off, so nothing
is generated; Tab still accepts a suggestion. The keys are handled only by the decorated main editor.
Terminals decide what arrives: Windows VS Code binds Ctrl+E to Quick Open, which the terminal never sees by default.

## Footer status

State goes out on `pi.events` channel `rqw-predictions:activity` as `{ sessionId, state, abortedUntil? }` with `state`
`brewing`, `aborted` or `idle` (`abortedUntil` is a `performance.now()` value). The stock `ui.setStatus` key
`rqw-predictions` always shows `prediction` and a maroon `prediction aborted`. RQW-statusbar hides that key and draws its own
indicator from the channel, so the status stays right after `/statusbar off`. A footer that starts later asks on
`rqw-predictions:activity-query` with `offer(state)` and gets the current state.

## Boundaries

- Own folder only; no import from another extension. Each of RQW-statusbar, RQW-skill-dollar and the transports can be off.
- The editor is decorated in place (`render`, `handleInput`); an editor shape other than border, one row, border stays stock.
- Not done: scrolling of a suggestion taller than the screen (it is drawn whole), and speed measurements on macOS and Windows.
- Tests: `test/extensions/RQW-predictions/`.
